Architecture

How Overseer turns Docker Compose metadata into a focused operational dashboard.

Components

The overseer Python package contains the complete application:

  • overseer/__init__.py exports the Flask application and create_app() factory.
  • overseer/__main__.py provides the development entry point.
  • overseer/app.py defines routes and translates Docker SDK objects and Compose labels into JSON-safe service metadata.
  • The templates provide the shared layout, project overview, dependency graph, and service controls.

Gunicorn imports overseer:app in the production container. Flask renders the dashboard while the Docker SDK connects through docker.from_env(), normally over a mounted Unix socket.

Request flow

  1. The browser requests the project overview, dependency graph, or service-control page.
  2. The overview requests GET /api/dashboard; the other pages request GET /api/services.
  3. Overseer detects its Compose project, queries matching containers, removes itself, and serializes project or container details. The overview also obtains one-shot resource metrics.
  4. A lifecycle button sends a CSRF-protected POST. Overseer verifies project membership before invoking Docker.

Current boundaries

Overseer filters by the com.docker.compose.project label when it can detect a project from its own container or from OVERSEER_COMPOSE_PROJECT. Local development outside Compose falls back to all visible containers.

Dependency edges come from com.docker.compose.depends_on; shared networks are not treated as dependencies. A custom request header protects lifecycle actions from cross-site form submissions, but the application does not authenticate users or stream events.

Design principle

Keep Docker-specific behavior in helper functions so routes remain straightforward to test.
